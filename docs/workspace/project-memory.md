# 项目记忆恢复

## 目标

为每个项目建立可恢复的工作区记忆。应用关闭或切换项目后，再次打开时应尽量回到上一次离开的现场，而不是只恢复项目列表。

## 记忆范围

每个项目都需要持久化以下状态：

- 最近一次打开的文件路径
- 左侧文件树的展开/折叠状态
- 右侧终端拆分的 pane 顺序
- 右侧终端每个 pane 的尺寸占比
- 右侧终端每个 pane 当前所在目录
- 右侧终端当前激活 pane
- 右侧终端是否处于分屏视图
- 右侧终端 session rail 宽度

全局仍保留当前激活项目。
最近项目列表也需要随着项目激活顺序更新，保证重启后仍能延续最近工作路径。

## 存储设计

使用 SQLite 作为唯一持久化来源，不再继续扩展 `state.json`。

建议表：

- `projects`
  保存项目基础信息
- `app_state`
  保存当前激活项目等全局状态
- `project_workspace_state`
  保存最近文件、文件树展开状态、终端 pane 尺寸、当前激活 pane、分屏视图状态、session rail 宽度
- `terminal_panes`
  保存每个项目的 pane 顺序与 cwd

要求：

- 项目级状态必须按 `project_id` 隔离
- pane 顺序和 pane cwd 必须独立存储，不能只从运行时推断
- 写入应在状态变化时立即发生，避免只在退出时落盘

## 恢复规则

### 项目恢复

- 启动时读取 SQLite 中的项目列表与当前激活项目
- 若存在激活项目，恢复该项目的文件树、预览和终端 pane

### 文件恢复

- 若最近打开文件仍存在，则恢复选中并拉取预览
- 若文件已不存在，则回退到当前快照中的第一个可选文件

### 文件树恢复

- 左侧文件树使用持久化的展开状态作为唯一初始值
- 不再把展开状态留在组件局部 `useState` 中

### 终端恢复

- 每个项目至少保留一个主 pane
- 若 SQLite 中存在多个 pane，按保存顺序重建
- 每个 pane 创建时优先使用保存的 cwd；无效目录回退到项目根目录
- pane 尺寸按保存值恢复；若 pane 数量变化或数据非法，则重新均分
- 当前激活 pane、分屏/聚焦视图、session rail 宽度都按上次状态恢复；字段缺失时回退到默认布局

## cwd 追踪

终端 cwd 不能只在创建时记录，必须在运行中持续更新。

实现约束：

- zsh / bash shell 启动时注入轻量 cwd hook
- hook 在 shell prompt 刷新时输出 cwd 标记
- 后端解析并剥离该标记，再把最新 cwd 写入 SQLite
- 不允许把内部标记显示到终端界面

## 前端状态约束

- 最近文件、文件树展开状态、终端 pane 尺寸、当前激活 pane、分屏视图、session rail 宽度属于项目级 store 状态
- 这些状态变化后要立即同步到 Tauri 后端
- 终端高频输出仍直接流向 xterm，不进入全局 store

## 验证重点

- 重启应用后，能回到上次选中的文件
- 重启应用后，文件树展开态与关闭前一致
- 多 pane 终端能按顺序和尺寸恢复
- 重启应用后，当前激活 pane、分屏/聚焦视图和 session rail 宽度与关闭前一致
- pane 在子目录执行 `cd` 后，重启应用仍从该目录恢复
- 删除项目后，对应记忆数据一并清理
